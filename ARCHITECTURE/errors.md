# Errors

## Goal

One error type for the crate and one exception hierarchy for Python, with a
total map between them. Every function that touches IO returns
`crate::error::Result`; every pyclass method that can fail converts at the
boundary and nowhere else.

The map has to be lossless in the direction that matters: a caller who writes
`except ProviderHTTPError as e` must be able to read `e.status_code`, which means
the exception classes cannot be generated by `create_exception!` and are
declared in Python instead.

This module owns the enum, its two classifiers, and the map. It does not own
retry policy, which is [provider.md](provider.md)'s, nor what a session does
with a classified failure, which is [agent-runtime.md](agent-runtime.md)'s and
[compaction.md](compaction.md)'s.

## Status

`done` — `cargo test -p kerness error` passes 14 tests and
`.venv/bin/python -m pytest bindings/python/tests -q -k error` selects 12
passing cases; the class-specific assertions are spread across the provider,
access, gameplan, persona, agent, and memory test modules named below.

## Language and Conventions

Rust crate module, one PyO3 binding module, and a Python module that declares
real classes. The root's [Coding Style and Code
Design](../ARCHITECTURE.md#coding-style-and-code-design) rules apply. Local
facts:

- `error.rs` imports nothing from the crate; every other module imports it.
  The enum derives `Serialize`/`Deserialize` (`crates/kerness/src/error.rs:16`)
  because `RunOutcome::error` (`crates/kerness/src/session/run.rs:157`) carries
  it through a checkpoint.
- Constructors are `Error::session(msg)` and `Error::provider(msg)`
  (`crates/kerness/src/error.rs:105`, `:110`) for the two string-carrying
  variants built most often; the rest are built as enum literals.
- The exception classes are Python (`bindings/python/kerness/exceptions.py:13`
  onward), handed to the extension at `bootstrap` and stored in a `OnceLock`
  (`bindings/python/src/errors.rs:28`). `register` tolerates a second call
  because re-importing the package re-runs `bootstrap` (`:42`).
- Every pyclass method that can fail ends in `.raise()` (`Raise`,
  `bindings/python/src/errors.rs:146`), and every call from Rust into Python
  ends in `.catch()` (`Catch`, `:157`); no boundary function hand-rolls the
  mapping. Observed across the binding modules, enforced by no lint.
- `NotFound`, `Value`, and `Io` map to CPython's built-in
  `FileNotFoundError`, `ValueError`, and `OSError` rather than to a framework
  class (`bindings/python/src/errors.rs:75`), because a missing file or a
  malformed one is the caller's typo, not a broken contract
  (`crates/kerness/src/error.rs:36`, `:41`, `:46`).
- The unit tests build HTTP errors with a local `http(status, body)` helper
  (`crates/kerness/src/error.rs:147`).

## Design and Invariants

One flat enum, which the bindings fan out into an exception class per variant.
The hierarchy is two levels below the base and callers branch on exactly one relationship
— "is this a provider error?" — so `is_provider` carries what a nested enum
would have cost a type to express. `Display` is the message a caller reads in
either language; `ProviderHttp` and `ProviderNetwork` format their fields into
it (`crates/kerness/src/error.rs:126`, `:131`) and the Python constructors
produce the same text (`bindings/python/kerness/exceptions.py:28`, `:47`).

### Recognising an overflow by phrase

`is_context_overflow` reads a `ProviderHttp` body rather than a status code,
because no backend gives the condition one: OpenAI and OpenRouter answer 400,
Anthropic 400 or 413, and all of them say what actually happened only in the
body. The status must still be 400 or 413 (`crates/kerness/src/error.rs:87`),
so a 500 whose body mentions context length is an outage, not a request to
shorten. A phrase list is wrong when a vendor rewrites its message, and it is
wrong in the safe direction — an unrecognised refusal stays an ordinary provider
failure, which is what a session does with it. The phrases live once, in
Rust; the Python property `ProviderHTTPError.is_context_overflow`
(`bindings/python/kerness/exceptions.py:31`) reads them through the pyfunction
at `bindings/python/src/funcs.rs:472` rather than restating them.

### Where `from_py` loses information

`from_py` (`bindings/python/src/errors.rs:92`) folds every unrecognised Python
exception into `Error::Session`, because `Error` has no variant that can carry a
Python class. For a Python callable the framework invokes, that changes what
`except` clause catches it: a test double raising `RuntimeError` spends the
retry budget and is then reported as a session error. Channels preserve their
original exceptions with the parked-exception pattern; see
[channel.md](channel.md). Tools and event sinks use the framework conversion and
are reported through tool results or the owned run's typed terminal outcome.

### Invariants

- **The map is total outward and nearly total back.** `to_py` matches every
  variant (`bindings/python/src/errors.rs:58`); `from_py` recognises every
  framework class plus `FileNotFoundError` and `ValueError` (`:108` onward),
  so those cross twice and come back as the variant they started as. `Io`
  does not: it leaves as `OSError` (`:77`) and there is no `OSError` arm, so
  it returns as `Session` (`:141`). `ProviderHttp` carries `status_code`,
  `url`, and `body` both ways (`:64`, `:109`); the Python-to-Rust direction is
  exercised for `status_code` and `body` by the tests named under **How to
  Test**, the Rust-to-Python attributes are unasserted, and no test drives a
  full Rust-to-Python-to-Rust round trip.
- **An overflow is still a provider error.** The retry and dialect-fallback
  paths must keep seeing it as one (`crates/kerness/src/error.rs:56`). Enforced
  by `an_overflow_is_still_a_provider_error` (`:176`).
- **The overflow test is narrow.** A 400 about an API key, a 400 about tools, a
  500 that happens to contain the phrase, and a non-HTTP provider error are all
  refused. Enforced by
  `a_refusal_about_length_is_told_apart_from_every_other_refusal`
  (`crates/kerness/src/error.rs:157`) and
  `TestContextOverflowDetection` (`bindings/python/tests/test_provider.py:751`).
- **Classification drives recovery.** `agent_runtime.rs:394` absorbs a provider
  error that is not an overflow into a placeholder under legacy error handling
  and lets an overflow propagate for [compaction.md](compaction.md)'s retry;
  `provider/mod.rs:456` gates capability fallback on `is_provider`;
  `memory.rs:618` keeps notes on a provider failure. Each site is tested by its
  own module.

## Key Types and Entry Points

- `crates/kerness/src/error.rs:17` — `Error` — one variant per exception class:
  `Provider`, `ProviderHttp { status_code, url, body }`,
  `ProviderNetwork { url, cause }`, `ProviderEmpty`, `Session`, `GameplanLoad`,
  `AccessDenied`, `NotFound`, `Value`, `Io`.
- `crates/kerness/src/error.rs:56` — `is_provider()` — true for the four
  provider variants; consulted after retry exhaustion for capability fallback
  and by compatibility paths that handle provider failures separately.
- `crates/kerness/src/error.rs:80` — `is_context_overflow()` — a `ProviderHttp`
  with status 400 or 413 whose body names a context-length phrase; the one
  provider failure a session can act on.
- `crates/kerness/src/error.rs:141` — `Result<T>` — the crate-wide alias.
- `bindings/python/src/errors.rs:31` — `register(module)` — stores the seven
  classes handed down by `bootstrap`; idempotent.
- `bindings/python/src/errors.rs:55` — `to_py(error)` — `Error` to `PyErr`,
  constructing the right class with the right arguments; falls back to the
  constructor's own failure if the class cannot be built.
- `bindings/python/src/errors.rs:92` — `from_py(py, error)` — `PyErr` to `Error`;
  a recognised class maps to its variant, `FileNotFoundError` and `ValueError`
  to `NotFound` and `Value`, anything else to `Error::Session` with its
  message.
- `bindings/python/src/errors.rs:146` — `Raise<T>` — `.raise()` on a
  `Result<T>`, used at every pyclass method return.
- `bindings/python/src/errors.rs:157` — `Catch<T>` — `.catch()` on a
  `PyResult<T>`, used wherever the framework calls into Python.
- `bindings/python/kerness/exceptions.py:21` — `ProviderHTTPError(status_code, url, body)` —
  the three-argument constructor the map has to preserve; `:41`
  `ProviderNetworkError(url, cause)` is the two-argument one.

## Interactions

- Returned by every module in the crate; `Result` is the return type of
  anything that reads a file, writes one, or calls a provider.
- Its classes are handed to the extension by [bindings.md](bindings.md)'s
  `bootstrap` (`bindings/python/src/lib.rs:41`), before any shim imports a
  name from `_core`.
- `is_provider()` gates capability fallback after retries in
  [provider.md](provider.md) and note preservation in [memory.md](memory.md).
- `is_context_overflow()` is what [agent-runtime.md](agent-runtime.md) lets
  through and [compaction.md](compaction.md)'s reactive pass acts on.
- [channel.md](channel.md) bypasses `from_py` for a raising Python channel by
  parking the original `PyErr`; [run.md](run.md) carries a converted `Error`
  in `RunOutcome::error` through the checkpoint.
- The `AccessDenied` variant is raised by [access.md](access.md) and, when a
  tool handler raises it, turned into a tool result rather than a session
  failure by [toolkit.md](toolkit.md).

## Review and Refactor Guide

- **Adding a variant** → `to_py` and `from_py` are exhaustive matches and
  chains; add the class in `bindings/python/kerness/exceptions.py`, its slot in
  `Classes` and `register` (`bindings/python/src/errors.rs:18`, `:31`), both
  directions of the map, the `__all__` list, and the re-export in
  `bindings/python/kerness/__init__.py`. `test_packaging.py` catches a missing
  `__all__` entry.
- **Changing a variant's fields** → `Display` (`crates/kerness/src/error.rs:115`),
  the serde shape carried in `RunOutcome::error`, the Python constructor's
  argument order, and both map arms.
- **Changing the overflow phrases** → the Rust test at `:157`, the Python
  parametrisation at `bindings/python/tests/test_provider.py:758`, and the
  reactive-pass test `TestAProviderRefusingALongRequestIsRetriedOnce` in
  `test_session.py`, which sends a body that must still match.
- **Changing `is_provider`** → the three call sites at
  `crates/kerness/src/agent_runtime.rs:394` and `:429`,
  `crates/kerness/src/provider/mod.rs:456`, and `crates/kerness/src/memory.rs:618`
  decide placeholder-versus-propagate, fallback, and note retention.
- **Safe extension points**: a new classifier is a method on `Error` beside
  the two existing ones; a new built-in Python exception mapping is a new
  `is_instance_of` arm in `from_py` and a new early return in `to_py`.
- **Forbidden coupling**: `error.rs` imports nothing from the crate, and
  `errors.rs` in the binding is the only place a `PyErr` becomes an `Error` or
  back.
- **Compatibility**: exception class names, their attribute names
  (`status_code`, `url`, `body`, `cause`), and `KernessError` as the common
  base are public; `Error`'s serde representation is part of the schema-2
  checkpoint.

Improvement candidates, as proposals:

- A round-trip test in `test_provider.py` that raises each class from a
  Python provider and asserts the same class and attributes reach the caller
  through `Session.run`. Success check: one parametrised case per class in
  the map passes, including `ProviderNetworkError`.
- Carry a structured path on `NotFound` and `Io` so a caller need not parse
  the message. Success check: `FileNotFoundError.filename` is set from Python.

## Open Gaps / Roadmap

- The `Error` enum carries strings, not structured context, for everything but
  the HTTP and network variants. A caller wanting the offending path out of a
  filesystem error has to parse the message.
- `from_py`'s fallback to `Error::Session` is coarse. Callbacks whose contract
  preserves an original Python exception need explicit parking; typed Rust
  outcomes retain the converted framework error. An `OSError` arm mapping back
  to `Error::Io` would close the one gap in the round trip; success check: a
  Python callback raising `OSError` surfaces as `Error::Io` in Rust.
